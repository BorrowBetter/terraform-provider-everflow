## 1. TL;DR: You are autonomous

You drive work end-to-end through five phases: Explore, Plan, Implement,
Staff Eng Review, PR. Do **not** ask the user for permission between
phases — just move through them. Use `AskUserQuestion` only for genuine

## 2. Workflow

**Skip phases for trivial changes** (typo, single-line fix, doc-only).
Still run `make lint && make test` before opening the PR.

**Phase 1 — Explore.** Read before you write. Use `Explore` subagent
for broad searches, `Glob`/`Grep`/`Read` for targeted lookups. If
adding a new resource, read an existing one end-to-end first.

**Phase 2 — Plan.** Use `EnterPlanMode` for non-trivial work. Be
concrete: list files, functions, tests. Get approval via `ExitPlanMode`.

**Phase 3 — Implement.** Dedicated tools for file ops; `Bash` only for
`git`, `make`, `gh`, `aws`, `terraform`, `curl`. Multi-commit layout:
one commit per meaningful unit. Run `make test` after each unit.

**Phase 4 — Staff Eng Review.** Launch a `general-purpose` subagent:
1. B1/B2/B3 invariants (section 5) — grep for violations
2. fetch-modify-put correctness (section 6) — Update GETs raw, overlays
   scalars, PUTs merged; Delete overlays ONLY the status field
3. Schema — new attrs Optional unless Required for POST; `time_saved`
   must NOT have `UseStateForUnknown`; immutable computed fields must
4. Test coverage — client + provider tests for every verb; named
   regression tests present
5. Cross-contamination — `internal/everflow/` must not import
   `terraform-plugin-framework`
6. `make lint && make test` passes

Apply BLOCKING findings as an additional commit before the PR.

**Phase 5 — PR.** `gh pr create` with Summary + Test plan body. Never
force-push. Never `--no-verify`. Title: `PR N/M: description (closes #X)`
for planned work; conventional commit style for standalone fixes.

## 4. The resource pattern

Read `internal/everflow/advertiser.go` + `internal/provider/advertiser_resource.go`
as the canonical example. Every new `everflow_<name>` needs:

1. **Client** (`internal/everflow/<name>.go`): typed struct with `json`
   tags, `Create<Name>Input`, and four methods — `Create`, `Get`,
   `GetRaw`, `Update`. No `Delete` (Everflow has no DELETE endpoint).

2. **Client tests** (`internal/everflow/<name>_test.go`): httptest-based.
   Create, Get, GetRaw (seed unmodeled nested objects), Update (merged
   body includes unmodeled surfaces), 404 → `IsNotFound`, 400 → `*APIError`.

3. **Resource** (`internal/provider/<name>_resource.go`): interface
   assertions at package scope, `<Name>ResourceModel` with `tfsdk` tags,
   full CRUD + ImportState, `fetchAndOverlay` helper, `write<Name>ToModel`
   helper with B1 normalization.

4. **Resource tests** (`internal/provider/<name>_resource_test.go`):
   - `SchemaImplementation` — ValidateImplementation + spot-checks
   - `CreateReadUpdateDelete` — full lifecycle, seed unmodeled surfaces
   - `InternalNotesClearOnUnset` — B1 regression guard
   - `ImportByID` + `ImportInvalidID`
   - `Read404RemovesFromState`
   - `Invalid<EnumField>` — one per validator

5. **Register** in `internal/provider/provider.go` Resources() slice.

6. **Examples**: `examples/resources/everflow_<name>/resource.tf` +
   `import.sh`. Use cross-resource references, not bare integers.

7. **Docs**: `make docs`, verify no drift (run twice, second is clean).

## 5. B1 / B2 / B3: named regression invariants

**B1 — Optional strings write `""` on null.** Everflow PUT is full
replacement; omitting a key does NOT clear the server value. Send `""`
explicitly. Read-side `write<Name>ToModel` normalizes `""` back to null
for a drift-free round trip. Guarded by `InternalNotesClearOnUnset`.

**B2 — `time_saved` has NO `UseStateForUnknown`.** Every PUT bumps
`time_saved`, so its planned value is genuinely unknown. Contrast with
`time_created` / `network_<res>_id` / `network_id` which are immutable
and DO use `UseStateForUnknown`.

**B3 — Delete overlays ONLY the status field.** `GetRaw → set status →
PUT`. Does NOT overlay name, notes, or any other schema-managed field.
Preserves out-of-band edits made before `terraform destroy`. Guarded by
`CreateReadUpdateDelete`'s `CheckDestroy`.

## 6. fetch-modify-put Update pattern

Everflow PUT is full replacement and we don't model many nested surfaces
(ruleset, traffic_filters, creatives, labels, etc.). The pattern:
`GetRaw` → overlay schema-managed scalars onto raw map → `Update` with
merged map. Unmodeled nested objects survive because they're never
overwritten.

For Optional strings, always write the value — `ValueString()` returns
`""` on null, satisfying B1.

**`relationship` wrapper gotcha:** some GET responses nest payloads
under `relationship` (e.g. offers: `relationship.payout_revenue.entries`).
POST/PUT expect the top-level shape. Solution: custom `UnmarshalJSON`
that handles both shapes (see `internal/everflow/offer.go`), plus
strip-on-PUT in `fetchAndOverlay`.

## 7. Schema choices

- **Minimum-viable surface**: POST-required fields + `internal_notes`.
  Defer everything else to fetch-modify-put.
- **`listvalidator.SizeAtLeast(1)`** alone does NOT fire on null
  (omitted) blocks. Pair with `listvalidator.IsRequired()`.
- **Enum validators**: keep permissive. Everflow returns undocumented
  sentinel values like `"null_value"` in production data. Strict
  validators break `terraform import`.

## 8. Testing patterns

- **Client**: httptest-based, one test per verb + 404 + 400.
- **Provider**: `UnitTest` + in-memory fake server. Shared helpers in
  `internal/provider/testing_test.go`.
- **Fake servers** track a mutable record + `lastPutBody`/`lastPostBody`
  side channel for wire-level assertions (this is how B3 is verified).
- **Always `-race`** (Makefile default).

## 9. Everflow API quirks

- Error bodies use `{"Error":"..."}` (capital E). See `internal/everflow/errors.go`.
- No DELETE endpoint. Soft-delete via PUT with status field.
- PUT is full replacement, NOT a patch. Omitted keys reset.
- GET sometimes nests under `relationship` (see section 6).
- Production data contains sentinel `"null_value"` for optional enums.
- Status enums differ per resource:

  | Resource   | Statuses                                 | Destroy value |
  |------------|------------------------------------------|---------------|
  | advertiser | `active`, `inactive`, `suspended`        | `inactive`    |
  | affiliate  | `active`, `inactive`                     | `inactive`    |
  | offer      | `active`, `paused`, `pending`, `deleted` | `deleted`     |

## 10. Smoke-test procedure (before tagging a release)

Mandatory. Caught two v0.1.0 blockers (PR #11) that unit tests missed.

1. `aws sts get-caller-identity` (if expired: `aws sso login`)
2. Load API key:
   ```sh
   export EVERFLOW_API_KEY="$(aws secretsmanager get-secret-value \
     --secret-id borrowbetter/terraform/variables \
     --query SecretString --output text \
     | python3 -c 'import json,sys;print(json.loads(sys.stdin.read())["everflow_api_key"])')"
   ```
3. `go build -o terraform-provider-everflow`
4. Create `TF_CLI_CONFIG_FILE` with `dev_overrides` pointing at repo root
5. For each resource: `terraform import` → `terraform plan` → `terraform plan`.
   The **second plan must be empty** (drift-free). If not, fix before tagging.

Known safe targets: advertiser id `1`, affiliate id `2`, offer id `2`.

## 11. Release / CI

- **`test.yml`**: PR + push to main. Build + vet + gofmt + test -race. No secrets.
- **`release.yml`**: tag push `v*`. GitHub OIDC → AWS assume-role
  (pinned to `refs/tags/v*`) → Secrets Manager GPG bundle → goreleaser.
- **`.goreleaser.yaml`**: 13 platform archives, GPG-signed SHA256SUMS,
  protocol 6.0 manifest.
- **Registry**: https://registry.terraform.io/providers/BorrowBetter/everflow
  (category: Web Services). Tag pushes auto-update after initial manual publish.
- **Gotcha**: tags created by `GITHUB_TOKEN` do NOT trigger other
  workflows. Push tags via PAT, GitHub App token, or local git.
